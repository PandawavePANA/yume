## 1. 검증이 끝나면 화면이 하얘지고 있었다 (`c95799b` · 운영 배포함)

**오늘 가장 중요한 건입니다.** 플레이스토어 준비 중에 우연히 찾았습니다.

`src/YumeDashboard.jsx`에 **`resultab_`** 라는, 어디에도 없는 이름이 네 곳 있었습니다.
그중 하나가 결과 화면을 그리는 자리입니다.

```jsx
{resultab_.id && (            // ← 결과가 그려질 때마다 실행된다
```

`result`가 `resultab_`로 바뀐 것이고, 같은 식으로 `checkout` → `checkoutab_`도 한 곳
있었습니다(요금제 결제가 끝나는 자리). 찾아 바꾸기가 잘못 돌아간 흔적입니다.

**증상**: 검증을 끝내면 결과가 나오는 대신 화면이 하얘집니다. 서비스의 핵심 기능입니다.
**범위**: 운영 번들에 그대로 들어 있었습니다(`index-BklIUlZp.js`에서 확인).

### 왜 아무도 못 잡았나 — 09-23과 똑같은 이유

| 신호 | 그때 값 |
|---|---|
| 서버 테스트 233개 | 전부 초록 |
| 빌드 | 통과 |
| `/api/health` | 정상 |

번들러는 **없는 이름을 그대로 두고 지나갑니다.** 서버 테스트는 프런트를 불러오지 않습니다.
09-23의 `useRef` 누락과 같은 종류이고, 그때도 브라우저로 열어봐야만 보였습니다.

### 그래서 이번엔 도구를 넣었다 (`fb0f5fa`, 브랜치)

ESLint를 넣고 규칙을 **두 개만** 켰습니다.

- `no-undef` — 없는 이름. 09-23과 오늘 건을 모두 잡습니다
- `react-hooks/rules-of-hooks` — 조건문 안의 훅

스타일 규칙은 켜지 않았습니다. 잔소리가 많으면 정작 중요한 경고가 묻힙니다.
돌리는 법은 `npm run lint`이고, 켜자마자 위 다섯 곳을 전부 짚어냈습니다.

### 배포와 확인

PG 심사 중이라 배포를 미루고 있었지만, **심사자가 검증을 한 번만 눌러도 보게 되는 화면**이라
이건 먼저 올렸습니다. 이름 다섯 개만 고친 최소 커밋입니다.

확인 순서(09-23 교훈대로):
