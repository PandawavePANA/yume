# 2026-09-28 작업일지 — 성능과 UI/UX

재고 나서 고쳤습니다. 헤드리스 크롬을 직접 조종하는 측정 도구(CDP)를 만들어, 폰 크기·4G·CPU 4배
느림 조건에서 전송량과 첫 그림 시각을 쟀습니다.

---

## 0. 가장 큰 병목 — 코드가 아니라 서버 위치입니다 (고치지 않음, 결정 필요)

| | 위치 |
|---|---|
| 사용자 | 🇰🇷 한국 |
| **DB (Supabase)** | 🇰🇷 **서울** (`ap-northeast-2`) |
| **앱 서버 (Railway)** | 🇺🇸 **미국 버지니아** (`iad` / `us-east4`) — yume·business·reamer 셋 다 |

**DB는 사용자 바로 옆인데, 그 DB와 대화하는 서버가 지구 반대편에 있습니다.**

```
/robots.txt   (DB 안 씀)   첫 바이트 ~480ms   ← 사용자 ↔ 버지니아 왕복
/api/health   (DB 1회)     첫 바이트 ~700ms   ← + 버지니아 ↔ 서울 왕복 ~200ms
```

- 사용자 요청 한 번마다 태평양 왕복 (~380ms)
- **DB 조회 한 번마다 또 태평양 왕복 (~200ms)**

크레딧 차감 한 번은 트랜잭션 안에서 DB를 6번 부르므로(BEGIN·잠금·잔액·기록·COMMIT) **차감만
1.2초**입니다. 로그인한 사람의 첫 화면(`/auth/me`)도 조회 3번이 차례로 돕니다.

**서버를 싱가포르(`asia-southeast1`)로 옮기면** 사용자↔서버 380→~70ms, 서버↔DB 200→~70ms.
어떤 코드 수정보다 큽니다. 다만 운영 인프라 변경이라(재배포, 나가는 IP 변경) 하지 않았습니다.
옮길 때 확인할 것: 포트원·카카오 웹훅 주소는 그대로, 법제처·Anthropic으로 나가는 IP가 바뀝니다.
Anthropic 호출은 반대로 약간 느려지지만(미국 → 싱가포르), 검증 한 건에서 몇 번뿐이고 한 번이
수 초짜리라 비중이 작습니다.

**크레딧 차감 트랜잭션은 합치지 않았습니다.** 한 번의 호출로 줄일 수는 있지만, 잠금을 잡은
**뒤에** 잔액을 다시 읽는 순서가 동시 결제의 이중 차감을 막고 있습니다. 한 문장으로 합치면
잔액을 잠금 **전** 스냅샷으로 읽게 되어 크레딧이 두 번 빠지는 틈이 생깁니다. 돈이 걸린 코드라
서버를 옮기는 쪽으로 안전하게 줄이는 게 맞습니다.

## 1. 정정 — 압축은 되고 있었습니다

처음에 "두 사이트 다 압축을 안 한다"고 말씀드렸는데 **틀렸습니다.** HEAD 요청으로 재서 압축
헤더가 안 보였던 것이고, 실제 GET으로 받으면 **유메는 gzip, 리머는 brotli**로 압축합니다
(유메는 Railway 엣지가, 리머는 `serve`가). 바이트로 확인한 값:

```
유메 JS  190,479 바이트 (gzip)
리머 JS   64,675 바이트 (brotli)
```

## 2. 리머 — 페이지 무게의 88%가 글꼴 파일 하나였습니다

| | 전 | 후 |
|---|---|---|
| 총 전송량 (폰 첫 방문) | **2,290KB** | **827KB** (−64%) |
| 글꼴 | 2,062KB | 586KB |

Pretendard **전체판**(한글 11,172자가 든 파일 하나, 2,011KB)을 받고 있었습니다. 유메는 처음부터
**분할판**(`dynamic-subset`)이라 화면에 나오는 글자 구역만 받습니다. 같은 글꼴이고 모양도 같습니다.

그리고 CSS 안의 `@import`로 부르고 있어서 **JS 받고 → CSS 읽고 → 그제야 글꼴 발견**하는 줄서기가
있었습니다. `reamer.html` 머리의 `<link>`로 올리고 `preconnect`를 붙였습니다.

## 3. 리머 — 한글이 "실 시 간  스 트 리 밍"으로 벌어졌습니다

고정폭 글꼴 목록(`--mono`)에 한글이 없어서, 한글이 **운영체제의 한글 고정폭**(윈도우 굴림체 계열)으로
떨어지고 거기에 영문용 넓은 자간이 붙었습니다. 페이지에서 뽑아 보니 **한글을 담은 넓은 자간 요소
11종이 전부** 이 경우였습니다(라벨·작업물 종류·기술 칩·연도 등).

요소마다 고치지 않고 `--mono`에 Pretendard를 대체 글꼴로 넣었습니다. `--serif`는 이미 이 패턴
("영문 글꼴 → 한글은 Pretendard")이었고 주석에 "의도한 것"이라고까지 적혀 있었습니다 —
고정폭에만 빠져 있었습니다.

## 5. 유메 — 폰 첫 화면

- **입력칸 안내가 잘렸습니다.** 다섯 줄이 폰에서 줄마다 두 줄로 접혀 7줄 입력칸을 넘쳤습니다.
  마지막 줄은 바로 위 부제목과 같은 말이라 뺐습니다 — 부제목이 못 하는 말(구체적 예시)만 남김.
- **안내 문구가 영어 화면에서도 한국어였습니다.** 상수로 빼 둔 탓에 `t()`를 안 거쳤고,
  `i18n:check`는 `t("…")` 안의 글자만 보므로 이런 자리를 못 잡습니다.
- **보조 버튼이 줄을 못 채웠습니다.** 「붙여넣기」「캡처 올리기」가 제 크기만 차지해 오른쪽이
  비었습니다. 폰에서는 둘째 줄을 반씩 나눠 씁니다 — 누를 자리도 커졌습니다.
- **섹션 간격**: 데스크톱용 200px이 폰에도 그대로였습니다. `clamp(96px, 16vw, 200px)`.
  데스크톱은 그대로, 폰에서는 96px. 폰 페이지 5,887 → 5,297px.

## 6. 유메 — 「캡처 올리기」가 눌리지 않던 것 (9-27에 적어둔 것)

떠다니는 「AI에게 물어보기」가 버튼 줄과 겹치는 동안 **비키도록**(투명 + 클릭 통과) 했습니다.

| 상황 | 떠다니는 버튼 | 캡처 버튼 탭 |
|---|---|---|
| 맨 위 | 보임 · 눌림 | — |
| 버튼 줄과 겹침 | 숨음 · 클릭 통과 | **캡처 버튼이 눌림** |
| 다시 위로 | 다시 보임 | — |
| 데스크톱 1440 | 늘 보임 | (겹치지 않음) |

위치는 움직이지 않습니다 — 옮기면 옮긴 자리에서 겹침이 풀리고, 풀리면 돌아와 다시 겹쳐 깜빡입니다.

### 어제 "안 켜진다"고 적은 것의 진짜 원인

**코드가 아니라 시험 환경이었습니다.** 앱 안 브라우저 창이 가려져 있으면 화면을 안 그려서
`requestAnimationFrame`과 스크롤 이벤트가 멈춥니다(`document.hidden = true`). 스크롤은 됐는데
이벤트가 0번 왔습니다. 헤드리스 크롬을 CDP로 직접 조종해서, 화면이 실제로 그려지는 상태에서
확인했습니다. 도구는 스크래치패드의 `cdp-*.mjs`.

## 7. 캐시

| | 전 | 후 |
|---|---|---|
| 유메 `/assets/*` (해시 붙은 파일) | 1시간 | **1년, immutable** |
| 유메 `index.html` | 기본값 | **no-cache** |
| 리머 `/assets/*` | **지시 없음** (브라우저 짐작) | **1년, immutable** |
| 리머 `index.html` | 지시 없음 | **no-cache** |

해시 붙은 파일은 내용이 바뀌면 이름이 바뀌므로 같은 이름은 영원히 같습니다. 1시간 캐시였을 때는
다시 온 사람의 브라우저가 매시간 "바뀌었냐"고 물었고, 그 한 번이 태평양 왕복이었습니다.
반대로 index.html은 절대 오래 쥐면 안 됩니다 — 옛 것을 쥐면 새 배포에서 사라진 JS를 찾다가
흰 화면이 됩니다. 두 규칙이 뒤바뀌어도 에러가 안 나서, 테스트로 못 박았습니다
(`server/tests/staticCache.test.js` 4개). 리머는 `serve.json`을 빌드 때 새깁니다.

## 8. 그 외

- **`/auth/me`의 조회 두 개를 동시에** 부릅니다(`peekUsage`: 오늘 사용량·크레딧 잔액). 서로를
  기다릴 이유가 없었습니다. 지금 구조에서 로그인한 사람의 첫 화면이 ~200ms 빨라집니다.
- **파비콘**: 1024×1024(36KB)를 탭 아이콘으로 쓰고 있었습니다. 64×64(2.4KB) + 아이폰 홈 화면용
  180×180을 따로 만들었습니다. 원본은 기업용 사이트의 공유 미리보기(og:image)에서 계속 씁니다.

## 확인하다 틀릴 뻔한 것 둘

- **리머 폰 화면에 상단 바가 없다**고 봤습니다. 전체 캡처에 고정 위치 요소가 안 찍힌 것뿐이었고,
  DOM으로 보니 로고·「내 의뢰」·「개발 문의」가 다 있었습니다.
- **유메 예시 카드가 흐리다**고 봤습니다. 스크롤 진행에 따라 선명해지는 효과라, 캡처가 맨 위에서
  찍혀 흐렸을 뿐 사용자가 내려가면 선명해지고 유지됩니다.

둘 다 확인 안 했으면 멀쩡한 걸 고쳤습니다.
