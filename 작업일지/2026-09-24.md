## 2. 앱에서 크레딧을 팔고 있었다 — 정책 위반 (가장 중요)

요금제 모달만 `IS_NATIVE_APP`으로 가려져 있었고, **계정 설정 → 크레딧 화면의 "결제하기 /

이대로 올렸으면 거절, 이미 올라간 뒤였다면 앱 내림까지 갈 수 있는 항목입니다.

## 3. 그래서 스토어용 빌드를 따로 만들었다 (`79889fc`, `284d8e9`)

웹을 건드리지 않는 것이 조건이었으므로(사용자 요청, PG 심사 중) **결과물을 나눴습니다.**

| | 웹 | 스토어 빌드 |
|---|---|---|
| 명령 | `npm run build` → `dist` | `npm run build:app` → `dist-app` |
| 주소 | `https://www.yume-reamer.com/` | `https://www.yume-reamer.com/app/` |
| 결제·구매 화면 | 그대로 있음 | **없음** |
| 검색 색인 | 함 | 막음(noindex) |

- `src/storeBuild.js` — `VITE_STORE_BUILD=play`일 때만 참. 웹 빌드에서는 거짓이라
  **웹 화면은 한 줄도 바뀌지 않습니다.** 로컬에서 `/`와 `/app/`을 나란히 열어 확인했습니다.
- `vite.app.config.mjs` · `app.html` · `scripts/rename-app-index.mjs` — 스토어 빌드 설정
- `server/app.js` — `/app`을 정적으로 서빙. 웹 catch-all보다 **앞에** 붙여야 합니다
- `capacitor.config.json` — `server.url`이 `/app/`을 가리킴
- `npm run build`가 둘 다 만들도록 묶었습니다. Railway는 이 명령 하나만 돌립니다

**같은 도메인 아래 둔 이유는 로그인입니다.** 다른 도메인에 두면 세션 쿠키가 교차 출처가 되어
앱에서 로그인이 풀립니다(`api.js`가 교차 출처일 때 `credentials: "omit"`을 씁니다).

## 4. 스크린샷을 코드로 찍게 만들었다 (`scripts/store-shots.mjs`)

09-13에 찍어 둔 스크린샷은 그 뒤 화면이 많이 바뀌어(사이드바 통합, 언어 전환, 상단 바)
지금 앱과 달랐습니다. 손으로 다시 찍으면 다음에 또 같은 일이 생기므로 스크립트로 만들었습니다.

```bash
node scripts/store-shots.mjs                  # 로그인 없이 찍히는 화면
node scripts/store-shots.mjs --with-result    # 검증을 실제로 돌려 결과 화면까지(과금·무료 3회 차감)
```

크롬을 `--remote-debugging-port`로 띄우고 CDP로 조작합니다(노드 22+의 전역 `WebSocket` 사용).
퍼페티어를 안 쓴 이유는 이 한 가지 일에 크로미움을 또 받을 필요가 없어서입니다.
폭은 CSS 360px에 3배로 그려 1080×1920을 만듭니다 — 1080을 CSS 폭으로 주면 태블릿 화면이 찍힙니다.

결과물은 `docs/app-store/screenshots/v2/`에 있습니다(홈 · 입력 · 확인 중).

### 찍다가 발견한 진짜 버그

**360px에서 "유메로 확인하기" 글자가 세 줄로 깨졌습니다.** 버튼 셋이 한 줄에 눌려 들어간
탓입니다. 좁은 화면에서는 줄을 나눠 주 버튼이 한 줄을 다 쓰게 고쳤습니다. 스크린샷을 찍지
않았으면 못 봤을 종류입니다 — **폰 화면은 폰 크기로 열어봐야 보입니다.**

### 헛다리 짚은 것 둘 (다음 사람이 같은 데서 헤매지 않도록)

- **완료 판정을 결과 문구로 재면 안 됩니다.** `확인됨`·`판정` 같은 낱말이 아래쪽 소개 글에도
  있어서, 시작하자마자 끝난 줄 알고 로딩 화면을 결과라고 찍었습니다. `확인하는 중`이
  사라지는 것으로 판단해야 합니다.
- **`document.body.innerText`에는 화면 밖 사이드바 글자도 들어옵니다.** 그걸 보고 "페이지가
  죽었다"고 오해했는데, 콘솔 오류 0건에 본문 2,069자로 멀쩡했습니다.
