# 유메 앱 출시 가이드 (앱스토어 + 플레이스토어 동시 출시)

## 이미 준비된 것

- **앱 구조**: Capacitor 8. 앱이 `https://www.yume-reamer.com`을 그대로 띄웁니다. 그래서 **웹사이트를 고치면 앱에도 바로 반영**되고, 스토어 재심사는 아이콘·권한 같은 네이티브 부분을 바꿀 때만 필요합니다.
- **네이티브 기능**
  - 스플래시 화면, 상태바 색상
  - 링크를 인앱 브라우저로 열기
  - 안드로이드 뒤로가기(모달·사이드바를 닫고, 결과 화면이면 입력 화면으로)
  - 결과 공유(시스템 공유 시트)
  - 오프라인 안내 화면
  - 노치·홈바 여백 처리
- **스토어 정책 대응**
  - 앱 안에서는 유료 플랜 "이용 문의(외부 결제 안내)" 버튼을 숨깁니다. 두 스토어 모두 디지털 상품을 앱 밖 결제로 안내하면 거절합니다.
  - 앱 내 계정 삭제는 이미 있고, 앱 밖 계정 삭제 안내 페이지(`/account-deletion`)를 추가했습니다.
  - 개인정보처리방침에 앱 항목을 추가했습니다.
- **프로젝트**
  - `android/`, `ios/` 네이티브 프로젝트
  - 앱 ID: `com.reamer.yume`
  - 앱 이름: 유메
  - iOS는 아이폰 전용(아이패드 스크린샷 불필요), 세로 고정
- **아이콘·스플래시·스토어 그래픽·스크린샷**: `docs/app-store/`
- **등록 문구**
  - 설명, 키워드, 심사 메모
  - 개인정보 설문 답변(앱스토어 개인정보 보호, 플레이 데이터 보안)
  - 모두 [스토어-등록정보.md](스토어-등록정보.md)에 있습니다.
- **안드로이드 업로드 키**: `android-signing/yume-upload.jks`
  - 비밀번호는 같은 폴더의 `README-업로드키.txt`에 있습니다.
  - 깃에는 올라가지 않게 막아뒀습니다.
  - 이 폴더는 **따로 안전한 곳에도 백업**하세요(비밀번호 관리자, USB 등).
- **클라우드 빌드 설정**: `codemagic.yaml`
  - 이 PC에는 맥과 안드로이드 SDK가 없어서, 두 앱 모두 Codemagic이 GitHub 코드로 대신 빌드합니다.
  - 무료로 월 500분까지 쓸 수 있습니다.

> ⚠️ **앱은 운영 웹사이트를 띄우므로, 이번 변경을 먼저 GitHub에 푸시(=Railway 배포)해야 앱이 제대로 동작합니다.**

## 0단계. 먼저 결정할 것: 개인 vs 법인(사업자) 계정

| | 애플 개발자 프로그램 | 구글 플레이 콘솔 |
|---|---|---|
| 비용 | 연 99달러 | 1회 25달러 |
| 개인으로 등록 | 판매자명이 "정원영"으로 표시 | **2023년 11월 이후 만든 개인 계정은 테스터 12명이 14일 연속 비공개 테스트를 해야 정식 출시 가능** |
| 조직(리머)으로 등록 | D-U-N-S 번호 필요, 판매자명 "REAMER" | D-U-N-S 번호 필요, **14일 테스트 의무 없음** |

**추천: 사업자등록이 되어 있으면 둘 다 조직 계정으로.**
- "동시 출시"를 하려면 구글의 14일 테스트 의무를 피하는 게 가장 큽니다.
- D-U-N-S 번호는 무료이고, 애플 개발자 사이트의 D-U-N-S 조회 페이지에서 신청합니다(보통 1~2주).
- 두 스토어에 같은 번호를 씁니다.
- 개인 계정으로 간다면 지금 바로 테스터 12명(지인)을 모아 두세요.

## 1단계. 이번 변경 배포 (5분)

1. 채팅에서 "푸시해"라고 답하면 제가 푸시합니다. Railway가 자동 배포합니다.
2. 배포 후 휴대폰 브라우저에서 아래 두 가지를 확인합니다.
   - https://www.yume-reamer.com/account-deletion 이 열리는지
   - 사이트가 새 디자인으로 보이는지
3. **심사용 데모 계정을 만듭니다.** 운영 사이트에서 이메일로 가입합니다(예: `appreview@d-reamer.com` 같은 받을 수 있는 주소). 이 이메일·비밀번호를 두 스토어의 심사 정보에 넣습니다.

## 2단계. Codemagic 연결 (15분)

1. https://codemagic.io 에 GitHub 계정으로 가입합니다.
2. **Add application**에서 `PandawavePANA/yume`을 고르고, 프로젝트 유형은 "codemagic.yaml"을 선택합니다.
3. **안드로이드 업로드 키 등록**: Team settings → codemagic.yaml settings → **Code signing identities** → **Android keystores** → Add keystore.
   - Keystore file: `android-signing/yume-upload.jks`
   - Keystore password / Key password: `README-업로드키.txt`의 비밀번호(둘 다 같음)
   - Key alias: `yume-upload`
   - **Reference name: `yume_upload_key`** (철자 그대로 — codemagic.yaml이 이 이름을 찾습니다)

## 3단계. 안드로이드 (플레이스토어)

1. https://play.google.com/console 에서 개발자 계정을 만듭니다. 결제와 본인/사업자 인증이 필요합니다.
2. **앱 만들기**에 아래 값을 넣습니다.
   - 앱 이름: `유메 - AI 답변 팩트체크`
   - 기본 언어: 한국어
   - 유형: 앱
   - 가격: 무료
3. Codemagic에서 **유메 Android (플레이스토어)** 워크플로 → **Start new build**를 누릅니다(약 10분).
4. 빌드가 끝나면 Artifacts에서 `app-release.aab`를 내려받습니다.
5. 플레이 콘솔 → **테스트 → 내부 테스트**에서 새 버전을 만들고 aab를 올립니다.
   - "Play 앱 서명"은 **Google에서 관리(기본값)** 그대로 두세요.
   - 테스터에 본인 구글 계정을 넣고, 휴대폰에 설치해 확인합니다.
6. **앱 콘텐츠**와 **스토어 등록정보**를 [스토어-등록정보.md](스토어-등록정보.md) 그대로 채웁니다. 스크린샷과 그래픽은 `docs/app-store`에 있습니다.
7. 출시 경로를 계정 종류에 따라 고릅니다.
   - **조직 계정**: 프로덕션 → 새 버전 → 같은 aab → 검토를 위해 전송
   - **개인 계정**: 비공개 테스트 → 테스터 12명 이상, 14일 유지 → 그 뒤 프로덕션 신청
8. 동시 출시하려면 **게시 개요 → 관리형 게시(Managed publishing)**를 켜 둡니다. 심사가 끝나도 내가 "게시"를 눌러야 공개됩니다.

## 4단계. iOS (앱스토어)

1. https://developer.apple.com/programs/enroll 에서 가입합니다. 조직이면 D-U-N-S가 필요하고 승인까지 1~2일 이상 걸립니다.
2. **번들 ID 등록**: developer.apple.com → Certificates, IDs & Profiles → Identifiers → + → App IDs → App.
   - Bundle ID: Explicit `com.reamer.yume`
   - 설명: Yume
   - 추가 기능 체크는 필요 없습니다.
3. **App Store Connect에서 앱 만들기**: https://appstoreconnect.apple.com → 앱 → + 신규 앱.
   - 플랫폼: iOS
   - 이름: `유메 - AI 답변 팩트체크`
   - 기본 언어: 한국어
   - 번들 ID: `com.reamer.yume`
   - SKU: `yume-ios`
4. **API 키 만들기**: App Store Connect → 사용자 및 액세스 → 통합 → App Store Connect API → 팀 키 생성.
   - 역할: 앱 관리
   - `.p8` 파일은 **한 번만** 내려받을 수 있으니 보관하세요.
   - Issuer ID와 Key ID를 적어 둡니다.
5. **Codemagic에 애플 연결**: Team settings → Team integrations → **Developer Portal** → Connect.
   - 이름: **`YUME_ASC_KEY`** (철자 그대로)
   - Issuer ID, Key ID를 넣고 `.p8` 파일을 올립니다.
6. **서명 인증서·프로필**
   1. Code signing identities → **iOS certificates** → Generate certificate. 종류는 Apple Distribution, 키는 방금 연결한 키입니다. 표시되는 인증서 비밀번호를 적어 둡니다.
   2. developer.apple.com → Profiles → + → **App Store Connect** 배포 프로필을 만듭니다(App ID `com.reamer.yume`, 방금 만든 인증서, 이름 `Yume App Store`).
   3. Codemagic → **iOS provisioning profiles** → Fetch profiles로 그 프로필을 가져옵니다.
7. Codemagic에서 **유메 iOS (앱스토어 · TestFlight)** → Start new build를 누릅니다(약 15~20분). 끝나면 자동으로 TestFlight에 올라갑니다.
8. 아이폰에 **TestFlight** 앱을 설치하고 유메를 받아 직접 써봅니다. 확인할 것:
   - 로그인
   - 검증
   - 결과 공유
   - 링크 열기
   - 계정 탈퇴 화면
9. App Store Connect에서 [스토어-등록정보.md](스토어-등록정보.md)를 보고 아래 항목을 채웁니다.
   - 설명, 키워드, 스크린샷(6.9형에 `ios-*.png`), 개인정보 보호, 연령 등급
   - 심사 정보(데모 계정·메모·연락처)
   - 빌드 선택
10. **버전 출시** 옵션에서 **"이 버전을 수동으로 출시"**를 고른 뒤 심사에 제출합니다. 보통 1~3일 걸립니다.

## 5단계. 동시 출시

- 두 스토어 모두 "수동 출시"(애플)와 "관리형 게시"(구글)로 심사를 통과시켜 둡니다.
- 출시일에 애플 **"이 버전 출시"**와 구글 **"게시"**를 같은 날 누르면 됩니다.
- 스토어 반영에는 몇 시간~하루가 걸립니다.

## 알아둘 위험 요소

- **애플 4.2(최소 기능) 거절 가능성**
  - 웹사이트를 띄우는 앱은 "웹사이트와 다를 게 없다"는 이유로 거절될 수 있습니다.
  - 공유 시트, 인앱 브라우저, 오프라인 화면, 뒤로가기 처리 같은 앱다운 동작을 넣고, 로그인 없이 핵심 기능이 되게 해서 가능성을 줄였습니다.
  - 그래도 거절되면 사유를 알려주세요. 푸시 알림(검증 완료 알림) 같은 네이티브 기능을 추가해 재제출합니다.
- **앱 안의 유료 결제**: 나중에 앱에서 유료 플랜을 팔려면 애플 인앱결제와 구글 플레이 결제를 붙여야 합니다(수수료 15~30%). 지금은 앱에서 "준비 중"으로만 보입니다.
- **다시 빌드해야 하는 경우**: 아이콘, 앱 이름, 플러그인, 네이티브 설정을 바꿀 때만 필요합니다. 두 워크플로를 다시 돌리면 빌드 번호가 자동으로 올라갑니다.
  - 출시 후 버전 이름(1.0.0)을 올리려면 아래 두 곳을 고칩니다.
  - `android/app/build.gradle`의 `versionName`
  - `ios/App/App.xcodeproj/project.pbxproj`의 `MARKETING_VERSION`
