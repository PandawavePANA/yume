# 유메 크롬 확장

ChatGPT·클로드·제미나이의 답변 옆에 **유메로 확인** 버튼을 붙인다.

## 왜 이 방식인가

AI 대화를 유메로 가져오는 길이 세 개인데 둘은 막혀 있다.

| 방법 | 상태 |
|---|---|
| 공유 링크 읽기 | **막힘.** ChatGPT 공유 링크는 서버 요청에 403을 준다(클라이언트 핑거프린팅). 앱 대화는 링크조차 없다 |
| 캡처 읽기 | 됨. 다만 읽는 값이 들고 잘못 읽을 위험이 있다 |
| **DOM에서 직접** | **이 확장.** 화면에 이미 글자가 있으니 읽는 값도, 틀릴 여지도 없다 |

## 구조

- `content.js` — AI 사이트에 버튼을 붙이고 글을 꺼낸다
- `fill.js` — 유메 쪽에서 그 글을 입력칸에 넣는다
- `background.js` — 탭 열기와 우클릭 메뉴

**글은 서버로 보내지 않는다.** `chrome.storage.local`에 담고 유메 탭에서 꺼내 쓴 뒤 지운다.
주소창에 실으면 길이 제한에 걸리고 접속 기록에도 남는다. 5분이 지난 것은 쓰지 않는다.

## 깨지지 않게 만든 방법

남의 사이트 구조는 예고 없이 바뀐다. 그래서 두 층으로 둔다.

1. **답변마다 버튼** — 선택자에 기대므로 언젠가 깨진다
2. **드래그하면 뜨는 버튼** — 구조를 안 보므로 깨지지 않는다

1이 죽어도 2는 남는다. 사용자는 기능이 사라진 게 아니라 손이 한 번 더 가는 것뿐이다.
우클릭 메뉴도 같은 이유로 둔다 — 아는 사이트가 아니어도 뜬다.

## 꺼낸 글은 바로 검증되지 않는다

유메 입력칸에 넣고 멈춘다. 라벨이나 UI 글자가 섞여 들어갈 수 있는데,
바로 검증으로 이어 버리면 사용자는 무엇이 검증됐는지 모른 채 결과만 본다.

## 설치 (개발 중)

1. `chrome://extensions` → 개발자 모드 켜기
2. **압축해제된 확장 프로그램을 로드** → 이 폴더 선택

## 스토어 등록 전 확인할 것

- [ ] 개인정보처리방침 주소 (확장이 다루는 데이터 기준으로 따로 필요)
- [ ] 권한 사용 사유 — `storage`(글 전달), `contextMenus`(우클릭), `scripting`(모르는 사이트에서 우클릭 시 주입), `activeTab`(도구막대 아이콘)
- [ ] 스크린샷 · 설명 · 카테고리
- [ ] `host_permissions`에 적힌 사이트가 실제로 쓰는 곳과 같은지
